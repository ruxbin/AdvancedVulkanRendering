# PBRT Exporter 修复计划与进度

> 执行方式：本会话直接实施，使用 executing-plans 的逐项验证与进度记录方式。

**Goal:** 修复审查文档中的 7 项问题，保留可重复执行的离线回归测试。

**Architecture:** 保持 `PbrtExporter::Export` 入口与场景数据访问方式。线性数据贴图采用 PFM，颜色贴图保留 BMP；在实际导出文件边界验证行为。测试用轻量场景 fixture 隔离 Vulkan 初始化，执行真实 exporter 源码；另编译真实应用验证集成。

**Tech Stack:** C++20、标准库文件 IO、Python unittest（测试构建/二进制图像读取）、现有 MSVC/CMake。

**Spec:** `docs/pbrt-exporter-review-2026-09-25.md`。

## 约束与决定

- 用户已要求按审查文档开始修复；沿用文档中的修复方向，不重复请求授权。
- 当前分支为 `texture_streaming`，实现直接保留在当前工作区；不提交、不推送，不覆盖已有 scene.pbrt/PLY/BMP。
- 不增加图像库：法线、GGX alpha 和遮罩使用 PFM（线性浮点，PBRT 原生支持），代价是文件比压缩图像大。
- BaseColor 和 emissive 的 BC sRGB 数据保持颜色语义；粗糙度按源格式先解码，再 clamp 到实时 shader 的 0.08 下限并平方。
- Cutout 使用 `alpha * opacity >= 0.1`；其他非不透明材质使用 alpha 覆盖率近似，不引入玻璃折射模型。该近似在最终文档中明确。
- 对可降级的纹理失败发出警告并使用常量；缺少必需几何或主文件/PLY 写入失败则返回 false。
- 数值灯光单位、金属模型和切线空间的全面校准不扩展进本次修复。

## Review focus

1. 同一源纹理的不同 opacity 不能错误共享处理后的遮罩。
2. 缺失纹理不应留下未定义引用；遮罩和 emissive 的降级应可解释。
3. 尺寸非 4 倍数和最后一行/列不能越界或倒置。
4. PLY 或主文件写入失败必须使返回值失败。
5. 粗糙度使用真实源颜色空间，避免把 sRGB 编码值直接平方。
